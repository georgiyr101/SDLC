# ADR-002: Трёхзвенная архитектура и хранение данных в удалённой СУБД PostgreSQL

## Контекст и постановка задачи

Система «Трекер финансов» включает три клиентские платформы: настольный клиент, мобильное приложение для Android и мобильное приложение для iOS (REQ-PORT-001, REQ-FUNC-031). Финансовые данные пользователя (счета, категории, операции, бюджеты) должны быть идентичны на всех устройствах (REQ-FUNC-026), храниться в PostgreSQL на удалённом сервере (CON-03, REQ-DIST-002), а прямой сетевой доступ клиентов к портам СУБД должен быть заблокирован (REQ-INT-006, REQ-SEC-008).

## Драйверы решения

- Исключение прямого доступа клиентов из интернета к порту базы данных (5432).
- Централизация финансовой математики, пересчёта лимитов и балансов на сервере.
- Гарантия целостности данных и транзакционности ACID при одновременных изменениях.
- Защита конфиденциальных персональных и финансовых данных при передаче по сети.

## Рассмотренные варианты

1. Трёхзвенная архитектура: клиенты обращаются по HTTPS к REST API Spring Boot, а сервер взаимодействует с удалённой PostgreSQL.
2. Двухзвенная архитектура: прямое подключение клиентов к PostgreSQL через JDBC поверх TCP/IP.
3. Локальные БД SQLite на каждом устройстве с последующей фоновой peer-to-peer синхронизацией.

## Итог решения

Выбран вариант 1. Клиентские приложения (Desktop, Android, iOS) не содержат параметров подключения к БД и драйверов JDBC. Взаимодействие происходит по протоколу HTTPS через REST API c авторизацией по токенам Bearer JWT (REQ-INT-008, REQ-SEC-006). Сервер приложений Spring Boot размещается на удалённом хосте, управляет пулом соединений HikariCP и обращается к закрытому порту PostgreSQL во внутренней сети Docker. Все расчёты лимита и агрегации выполняются на сервере.

### Последствия

- Клиенты полностью изолированы от реляционной схемы базы данных и изменений структуры таблиц.
- Миграции схемы выполняются централизованно через Flyway при старте сервера.
- При отсутствии подключения к интернету клиенты выводят сообщение о недоступности сети без аварийного завершения (REQ-REL-004).

### Подтверждение

Сканирование портов удалённого сервера подтверждает закрытый порт 5432 для внешних IP-адресов. Автоматические тесты проверяют изоляцию арендаторов (REQ-SEC-007) и транзакционность проводок (REQ-REL-001).

## Плюсы и минусы вариантов

| Вариант | Плюсы | Минусы |
|---|---|---|
| Трёхзвенная (Spring + Postgres) | Безопасность БД, единая бизнес-логика, единые токены сессий | Необходимость поддержки и хостинга серверного процесса |
| Прямое JDBC-подключение | Меньше компонентов (нет REST-слоя) | Критическая уязвимость: раскрытие реквизитов БД, открытие порта 5432 |
| Локальные SQLite на клиентах | Работа без интернета | Конфликты синхронизации, рассинхронизация копеек, противоречит CON-03 |
