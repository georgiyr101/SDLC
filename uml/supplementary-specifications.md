# Дополнительные спецификации (Supplementary Specifications)

**Проект:** «Трекер финансов» (Desktop JavaFX, Android, iOS, Spring Boot API, PostgreSQL)  
**Версия:** 1.0  
**Дата:** 16.11.2026  
**Основа:** Спецификация требований к ПО (SRS v0.2), Описание дизайна (SDD v1.0), ADR-001..ADR-003

---

## 1. Назначение документа

Настоящий документ дополняет модель вариантов использования (Use Case) и описывает сквозные системные требования, атрибуты качества (нефункциональные требования), технические и проектные ограничения, которые применяются ко всей системе «Трекер финансов» в целом и не привязаны к одному отдельному прецеденту.

---

## 2. Функциональность общего характера (Общие системные правила)

1. **Единый источник истины на сервере (`REQ-SEC-004`, `REQ-FUNC-026`):**
   - Все финансовые данные (счета, транзакции, категории, месячные лимиты, правила автоплатежей) хранятся исключительно в централизованной СУБД PostgreSQL 16.
   - Клиентские приложения (Desktop JavaFX, Android Compose, iOS SwiftUI) не содержат локальной реляционной БД финансовых операций и работают с сервером через единый REST API `/api/v1/...` (`REQ-INT-008`).
2. **Денежная арифметика (`CON-04`, `REQ-REL-003`):**
   - Любые вычисления балансов, сумм переводов, процентных лимитов и остатков выполняются строго в `java.math.BigDecimal` с масштабом 2 знака после запятой и правилом округления `RoundingMode.HALF_UP`.
   - Использование типов с плавающей запятой (`float`, `double`) для денежных значений запрещено на всех слоях системы.
3. **Защита от некорректного аудита и утечек в логах (`REQ-OBS-001`):**
   - Серверное журналирование (SLF4J / Logback) фиксирует идентификаторы ошибок, статусы планировщика и время отклика без записи паролей, JWT-токенов, PIN-кодов и денежных сумм в открытом виде.
4. **Детерминированность алгоритмов (`REQ-FUNC-011`, Раздел 3.6 SRS):**
   - Автоматическая категоризация и планирование регулярных платежей работают строго по детерминированным правилам без компонентов машинного обучения.

## 3. Удобство использования и интерфейс (Usability)

1. **Платформенная адаптация (`REQ-INT-001`, `REQ-INT-009`):**
   - **Desktop (JavaFX 21):** боковая навигация, разрешение от 1024×720, полная поддержка навигации с клавиатуры (`Tab`, `Enter`, горячие клавиши форм).
   - **Android (Jetpack Compose):** нижняя панель навигации Material 3 (`BottomNavigationBar`), экраны шириной от 360 dp, сенсорные зоны кнопок не менее **48×48 dp**.
   - **iOS (SwiftUI):** нижняя панель вкладок Apple HIG (`TabView`), экраны шириной от 375 pt (iPhone SE и выше), сенсорные зоны не менее **44×44 pt**, корректная обработка Safe Area и Dynamic Island.
2. **Информационная доступность для людей с особенностями цветовосприятия (`REQ-INT-004`):**
   - Светофорная индикация лимита всегда дублируется текстовой меткой и пиктограммой:
     - `< 80%` — «Норма» (зелёный + галочка);
     - `80%..100%` — «Предупреждение» (жёлтый + треугольник);
     - `> 100%` — «Превышен» (красный + знак «Стоп»).
3. **Удобство мобильного ввода (`REQ-INT-002`, `REQ-INT-009`):**
   - Для полей «Сумма» и «Процент лимита» на смартфонах автоматически открывается цифровая клавиатура; текущая дата подставляется по умолчанию.

## 4. Надёжность (Reliability)

1. **Транзакционная целостность (`REQ-REL-001`):**
   - Проводки доходов, расходов, межсчётных переводов и автоматических списаний выполняются в рамках ACID-транзакций PostgreSQL с уровнем изоляции `READ COMMITTED` и оптимистичной блокировкой (`@Version`) при обновлении счетов.
   - При сбое записи баланса или обрыве транзакции выполняется полный откат (`ROLLBACK`).
2. **Устойчивость планировщика к дублированию (`REQ-FUNC-008`):**
   - Служба `RecurringPaymentService` фиксирует дату последнего успешного начисления `last_executed_date` в той же транзакции БД, что и создание проводки. Повторный прогон планировщика в те же сутки не создаёт дублирующих транзакций.
3. **Устойчивость клиентов при обрыве сети (`REQ-REL-004`):**
   - При потере соединения клиенты не сбрасывают заполненные поля формы добавления транзакции, выводят понятное уведомление и предлагают кнопку «Повторить».
4. **Доступность и резервное копирование (`REQ-AVAIL-002`, `REQ-REL-005`):**
   - Целевая доступность серверного API — не менее 99.0% в месяц; ежедневное резервное копирование БД с глубиной хранения 7 суток.

## 6. Безопасность (Security)

1. **Защита канала и периметра (`REQ-SEC-005`, `REQ-SEC-008`):**
   - Весь клиент-серверный трафик шифруется по HTTPS (TLS 1.2 / 1.3 через NGINX Reverse Proxy).
   - Порт PostgreSQL `5432` изолирован во внутренней сети Docker и недоступен из интернета.
2. **Хранение учётных данных (`REQ-SEC-006`, `REQ-FUNC-025`):**
   - Пароли хранятся только в виде солёных хешей BCrypt (cost factor ≥ 12).
   - Токены доступа на смартфонах сохраняются в Android KeyStore и Apple iOS Keychain.
3. **Биометрия и PIN-код (`REQ-SEC-002`):**
   - Локальная разблокировка работает только при наличии действительного Refresh-токена.
   - После 3 подряд неудачных попыток ввода PIN-кода или сбоев биометрии клиент сбрасывает локальную разблокировку и требует полную авторизацию по Email и паролю.
4. **Защита от SQL-инъекций и мультитенантность (`REQ-SEC-003`, `REQ-SEC-007`):**
   - Все запросы к PostgreSQL параметризуются через Spring Data JPA, входящие DTO проходят Bean Validation (`@Valid`), а выборки данных жёстко фильтруются по `user_id` из Bearer JWT.

## 7. Поддерживаемость и архитектурные ограничения (Supportability & Constraints)

- **Технологический стек (`CON-01`..`CON-03`):** Java 17+, Spring Boot 3, PostgreSQL 16, JavaFX 21 (Desktop), Kotlin + Jetpack Compose (Android 10+), Swift + SwiftUI (iOS 16+).
- **Модульность (`REQ-MAINT-001`, `REQ-MAINT-002`):** строгая слоистая архитектура `Controller → Service → Repository`; покрытие сервисного слоя модульными тестами JUnit 5 не менее 70%.
- **Правовое и лицензионное соответствие (`REQ-COMP-001`..`REQ-COMP-003`):** используются библиотеки с открытыми бесплатными лицензиями (MIT, Apache 2.0); обработка ПД соответствует Закону РБ № 99-З «О защите персональных данных».
- **Бюджетно-календарные рамки (`CON-06`, `CON-07`):** поставка версии 1.0 к **27 ноября 2026 г.** при сметной стоимости **$1 840** (команда Middle 80 ч + Junior 24 ч).
